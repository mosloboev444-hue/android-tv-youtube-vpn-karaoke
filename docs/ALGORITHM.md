# Алгоритм

## Задача

На телевизоре YouTube TV не работает без VPN: трафик YouTube замедляется/блокируется. VPN-клиент
Юбуст умеет «Только YouTube», но включает туннель только по кнопке в своём интерфейсе. Always-on VPN
на Philips Android TV 14 не запускает Юбуст: система поднимает `VpnService`, но приложение не
устанавливает туннель. Публичного intent'а «подключиться» у Юбуста нет.

Поэтому автоматика работает на `AccessibilityService`: она видит, какое окно на экране, и может
нажать кнопку в другом приложении.

## Состояния

| Состояние | Что происходит |
|---|---|
| `IDLE` | Раз в 3 с проверяет: YouTube в фокусе и `tun0` нет? Тогда `OPENING`. |
| `OPENING` | Открывает Юбуст. Пока он грузится, каждые 400 мс ищет кнопку «Подключить». |
| `CLICKED` | Кнопка нажата, ждёт `tun0`. Если через 7 с туннеля нет — нажимает ещё раз (до 3 попыток). |
| `IDLE` после успеха | Перезапускает YouTube и сбрасывает состояние. |

Таймаут одной попытки — 30 с. После неудачи — пауза 20 с, чтобы не бороться с пользователем,
который в этот момент сам открыл Юбуст.

## Определение VPN

`ConnectivityManager.getAllNetworks()` не видит VPN-сеть, когда Юбуст работает в режиме «Только
YouTube»: приложение исключено из списка разрешённых, и система прячет от него VPN-сеть. Поэтому
проверяется наличие поднятого интерфейса:

```java
NetworkInterface.getNetworkInterfaces()
// tun*, wg*, ppp* + isUp()
```

Для этого в манифесте есть `android.permission.INTERNET`; приложение не открывает соединений,
разрешение нужно только перечислению интерфейсов.

## Возврат в YouTube

Если YouTube уже был открыт до включения VPN, он остаётся на экране «Нет подключения к сети».
Обычный `startActivity` лишь поднимает существующую activity, и ошибка остаётся. Поэтому YouTube
запускается с `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK`: задача очищается и приложение
стартует заново, уже с туннелем.

Для кнопки «Караоке!!!» используется `ACTION_VIEW` c
`https://www.youtube.com/results?search_query=караоке` — эта ссылка проверена на YouTube TV
(открывает именно поиск). `CLEAR_TASK` обязателен и здесь, иначе YouTube проигнорирует новый URI.

## Кнопка «Караоке!!!»

1. Плитка в лаунчере запускает `KaraokeActivity`.
2. Activity показывает огонь и отправляет широковещательный intent `com.gathin.vpngate.KARAOKE`
   (same-app, `RECEIVER_NOT_EXPORTED`).
3. Служба получает его, ставит `karaokePending = true` и либо сразу открывает YouTube-поиск (если
   `tun0` уже есть), либо запускает сценарий подключения.
4. После подключения открывает YouTube-поиск и сбрасывает флаг.

Если служба доступности выключена, через 6 секунд срабатывает запасной путь: activity сама
открывает YouTube-поиск (без VPN).

## Поиск кнопки в Юбусте

1. `findAccessibilityNodeInfosByText("ПОДКЛЮЧИТЬ")` — основной путь.
2. Обход дерева вручную, если Compose не отдал текст через стандартный поиск.
3. Если текста нет вообще — самая большая кликабельная область в правой половине экрана (круглая
   кнопка подключения). Кнопка «Отключить» никогда не нажимается: если на экране есть
   «ОТКЛЮЧИТЬ»/«DISCONNECT», шаг пропускается.
4. После `ACTION_CLICK` — резервный tap через `dispatchGesture`.

## Ограничения

- Юбуст обновляется — текст/разметка могут измениться; резервный поиск большой кнопки помогает не
  всегда.
- Любой другой VPN-клиент потребует правки констант и, возможно, логики.
- Служба доступности — мощное разрешение; включайте её только на своём телевизоре.
